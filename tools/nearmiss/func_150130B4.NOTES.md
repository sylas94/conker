## HEADLINE — THE BANKED `|= 0x2006` SPLIT IS NOT SUPPORTED BY OUTPUT EVIDENCE
---------------------------------------------------------------------------
Last wave banked this change and justified it by instruction count:

    -   flags = (fade ? 0x1000000 : 0) | 0x2006;      405 instrs
    +   temp = (fade ? 0x1000000 : 0);                406 instrs  <- "adds the missing one"
    +   temp |= 0x2006;

**That justification is wrong.** An alignment diff (shape-normalised, so a row that merely
MOVED is not counted as wrong) shows what each form actually gets wrong:

| source form                       | n   | mism | shape_miss | golden-only | ours-only  |
|-----------------------------------|-----|------|-----------|-------------|------------|
| banked base (split, 406)          | 406 | 227  | 22        | `nop` x1    | `move R,R` x1 |
| any single-statement form (405)   | 405 | 254  | 24–25     | `nop` x1    | **(none)** |

So the split did not add golden's missing instruction. It added a **spurious `move v0,t7`**,
and golden's extra instruction is a **scheduler `nop`** (golden row 65, the `mtc1`→`cvt.s.w`
hazard in the `desc.unk04` block, which golden had no work left to fill). The counts agree at
406 by coincidence — one wrong instruction standing in for another.

The `move` exists because the base assigns `temp` from the ternary alone, so IDO homes `temp`
in **v0** (the conditional-expression result register) and the later `ori` has to be moved back
into it. Golden never does this: its flag word is a pure temp chain `t2 → t1 → t3 → t4 → t5 → t1`
and case 19 reads it straight out of a register (`and t8,t1,at`, no reload). **Golden's flag word
lives in t1, ours lives in v0.** That is the single most actionable fact in this file.

Keep the banked base as the search start (it is still the best `mism`), but stop treating 406
as evidence of correctness, and prefer a 405-instruction form when judging *content*.
