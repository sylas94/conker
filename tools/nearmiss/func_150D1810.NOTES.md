## Why the permuter cannot be used on this one

`conker/permuter_tu.sh selftest` reaches **(b2) FAIL: round trip changes codegen**.
The harness preprocesses the region before handing it to pycparser, so the `gSP*`/`gDP*`
macro bodies are expanded onto their own source lines. Under `-O2 -g3` that changes the
line attribution and therefore the schedule: the round-tripped base scores 1225 where the
real base is ~69-equivalent. Any search from that baseline is optimising a different
function. **This applies to every macro-heavy display-list builder in the project**, not
just this one — do not spend the setup time again without fixing the harness to permute
the *unpreprocessed* region.

Two harness bugs found and worth knowing:

1. `permuter_tu.sh setup <...> [dir]` must be given a **space-free** directory (use `/tmp/...`).
   `compile.sh` `cd`s into `conker/` and passes `-o "$OUT"`; the recompiled IDO `cc` silently
   writes **no object** when the output path contains a space, and the selftest then reports
   the empty-string sha1 `da39a3ee...0709` for (b) and (b2), plus "no base score" for (c).
   With `dir=/tmp/perm1810` the same TU passes (a), (b), (c) and (d).
2. The `<dir>` argument must be absolute for the same reason.

## Next lever to try if someone picks this up

between the `func_150950D4` call and the first `gSPMatrix`, in code that is otherwise
